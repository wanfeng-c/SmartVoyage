# SmartVoyage 前端设计与实现文档

> 定位：**明亮冰雪幻想场景 × 二次元游戏 HUD × AI 旅行助手**
> 范围：仅前端（`static/index.html`、`static/style.css`、`static/app.js`）
> 约束：原生 HTML/CSS/JS、零 CDN、零构建；后端与数据流程一行未改

---

## 1. 这一版的核心变化

上一版是"深色 AI 工作台"：深蓝黑面板、暗色舞台、克制的发光。本次按新方向整体转为**明亮冰雪游戏场景**：

| 维度 | 之前 | 现在 |
|---|---|---|
| 画布 | 深蓝黑 `#080F19` | 浅天空蓝 `#EAF5FC` + 提亮插画 |
| 面板 | 深色实体 | 浅色玻璃 `rgba(241,249,254,.78~.94)` + 白边 + 蓝灰阴影 |
| 舞台 | 不透明深色 | 上下渐变：上部透出角色，下部为阅读底板 |
| 插画 | 压暗到 52% | 提亮到 116%、饱和 120%，白蓝薄雾罩 |
| 粒子 | 50+ 深色氛围 | 背后雪晶 + 前景柔光球/星芒双层，总 60 左右 |
| 装饰 | 无 | 冰晶水印、面板角线、光带扫过、雪晶徽记 |

保留：三栏结构、全部组件与业务含义、13 个工具时间线、真实天气/状态、会话、SSE 流程、无障碍能力。

## 2. 配色与材质

### 2.1 令牌职责

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--canvas` | `#EAF5FC` | 页面底色（多数被面板覆盖） |
| `--panel` / `--panel-strong` | `rgba(241,249,254,.78)` / `(248,252,255,.90)` | 顶栏、侧栏、情报面板 |
| `--panel-raised` | `rgba(255,255,255,.94)` | 快捷卡、输入框 |
| `--panel-inset` | `rgba(230,243,250,.94)` | 工具时间线、代码块 |
| `--brand` | `#398FC7` | 主操作底色、图标、大字号强调 |
| `--brand-strong` | `#2474A8` | 小字号文字强调（对比度修正） |
| `--text-primary/secondary/muted` | `#183A54` / `#3F6078` / `#53708A` | 标题 / 正文 / 辅助 |
| `--line` / `--line-strong` | 蓝灰 18% / 38% | 分隔线 / 控件边框 |
| `--success/warning/danger` | `#21886F` / `#A66A16` / `#C65066` | 仅状态，且必配文字 |

对比度实测（1440 渲染图取样）：
- 标题 `#183A54` 在人物插画上 **9.3–10.5 : 1**
- 正文 `#3F6078` 在面板/欢迎区 **5.2–6.3 : 1**
- 辅助文字 `#53708A` 在浅蓝面板 **4.6 : 1**
- 小号品牌文字 `#2474A8` **4.5 : 1**

### 2.2 面板材质

```css
background: linear-gradient(180deg, rgba(253,254,255,.90), rgba(238,248,254,.84));
border: 1px solid rgba(255,255,255,.92);
box-shadow: 0 0 0 1px rgba(126,178,212,.17),
            0 10px 32px rgba(55,103,134,.15),
            inset 0 1px 0 #fff;
backdrop-filter: blur(22px) saturate(1.14);
```

三重边界（白描边 + 冷色外环 + 白内高光）让面板在明亮场景上依然有清晰轮廓，而不需要暗色投影。

### 2.3 舞台：一面上透明、下面实底的"场景窗"

```css
.stage {
  background: linear-gradient(180deg,
    rgba(250,253,255,.08) 0%,   /* 顶部：几乎透明，角色清晰 */
    rgba(248,252,255,.22) 24%,
    rgba(247,252,255,.78) 46%,  /* 中段：开始压白 */
    rgba(246,251,255,.94) 70%,  /* 阅读区：稳定底色 */
    rgba(246,251,255,.96) 100%);
}
body.thread-open .stage {       /* 进入对话：整体转为可读底 */
  background: linear-gradient(180deg, rgba(250,253,255,.91), rgba(246,251,255,.95));
  backdrop-filter: blur(18px) saturate(1.06);
}
```

这是"场景里放 HUD"的关键：欢迎页能看见角色，一旦开始对话就自动让位给正文。
`thread-open` 由 `showThread()/showWelcome()` 切换，纯表现层，不影响数据流。

## 3. 背景处理

- 插画本体：`brightness(1.16) saturate(1.2) contrast(1.01)`，`background-position: 30% 28%`，角色头部落在舞台左上方。
- 薄雾罩：两层线性渐变（白蓝 0.40→0.16→0.34→0.46 + 横向 0.34→0.04→0.22），只提亮不压暗。
- 高光：角色区域一枚 `screen` 混合的白色柔光，加右上暖光点缀。
- 暗角改为**白色雾化暗角**（`rgba(212,234,248,.44)`），边缘更通透不脏。
- 冰面光带：一条 26s 循环的斜向白色光带，缓慢掠过整个场景。

### 3.1 中央舞台的局部曝光控制

全页提亮后中央插画一度过曝（顶部区域 40% 像素亮度 > 0.90）。为避免压暗整页，只在**舞台自身**做局部校正：

```css
.stage {
  backdrop-filter: saturate(1.12) brightness(.85) contrast(1.02);
  background: linear-gradient(180deg,
    rgba(222,238,249,.20) 0%,   /* 顶部加一层极淡冷调，中和白色高光 */
    rgba(232,244,252,.16) 24%,
    rgba(247,252,255,.78) 46%,
    rgba(246,251,255,.94) 70%,
    rgba(246,251,255,.96) 100%);
}
```

`backdrop-filter` 只作用于舞台背后的插画，左右栏与顶栏完全不受影响。
实测同一区域：平均亮度 0.843 → 0.79，亮度 >0.90 的像素 40.7% → 约 10%，>0.95 的像素 17.6% → 1.5%，
花海与服饰纹理重新可见，整页仍然是明亮的冰蓝色调。

不使用任何黑色全屏蒙层；所有对比度都靠"局部白底 + 面板不透明度 + 排版位置"解决。

## 5. 动效体系

### 5.1 背景氛围（持续、可感知）

| 层 | 内容 | 参数 |
|---|---|---|
| 场景 | 插画缓慢视差 | 指针 ±9px，`lerp .045` |
| 后景粒子 | 雪点 26 / 冰晶 8 / 花瓣 5 / 星光 12 / 光斑 3 | 小屏减半，DPR ≤ 2 |
| 前景层 | 柔光球 9 + 冰晶星芒 8 | 缓慢上浮，透明度 .10–.55 |
| 光带 | 斜向白色扫光 | 26s 线性循环 |
| 极光 | 三团 80px 模糊色块 | 30/38/46s 往复 |
| 鼠标 | 白色柔光跟随 | 透明度 .5s 渐显 |

实测：静止播放时，1.1 秒内约 **8.2%** 的像素发生变化，动效在整页范围内可见。

### 5.2 入场（约 640ms，分层错峰）

场景淡入 1s → 顶栏下落 520ms → 左栏左滑 620ms → 舞台上升 640ms → 情报右滑 620ms；
欢迎内容内部再分四层：眉标（260ms）→ 标题（320ms，模糊→清晰的 `titleReveal`）→ 说明（420ms）→ 快捷卡（500–680ms 阶梯）→ 说明行（740ms）。

### 5.3 交互微动效

| 触发 | 反馈 |
|---|---|
| 新建对话悬停 | 高光横扫（900ms）+ 上浮 1px + 阴影加深 |
| 服务菜单悬停 | 底色转浅蓝、图标右移 1px 并放大 6%、左侧 2px 指示条 0→16px |
| 快捷卡悬停 | 上浮 3px、边框转冰蓝、图标旋转 −3°、跟随鼠标的光斑、箭头滑入 |
| 输入框聚焦 | 边框转冰蓝、4px 低透明焦点环、左侧冰晶徽记旋转 180° |
| 会话选中 | 白底 + 冰蓝左边条 + 轻微投影 |
| 抽屉 | 380ms 滑入 + 浅色遮罩淡入 |
| Toast | 上滑 10px + 缩放 0.97 → 1 |

### 5.3.1 左右面板的内容动效

| 位置 | 动效 | 触发条件 |
|---|---|---|
| 历史会话列表 | 逐条 `listIn`（上移 5px + 淡入，间隔 35ms，最多 400ms） | **仅首次渲染**，之后更新不重复播放，且渲染前后保留 `scrollTop`，列表不跳动 |
| 刷新按钮 | 点击后图标旋转（`spinSlow 0.9s`）+ 冰蓝底，最少持续 420ms，并写 `aria-busy` | 真实点击，等接口返回后复位 |
| 右侧三块情报 | `panelIn`（右移 10px + 淡入）错峰 160 / 240 / 320ms | 页面首次进入 |
| 天气卡出现 | `wxIn` 上浮 8px；标题、气温、日期、6 格数据、来源依次 40–440ms 阶梯淡入 | `get_weather` 返回并成功解析后 |
| 天气空状态 | 冰晶图标 6s 浮动 + 外圈 18s 慢转虚线环 | 空状态常驻，低速不抢注意力 |
| 系统状态变化 | 状态点 `statusPop`（0.55→1.35→1 缩放）+ 文字淡入，整行高亮 700ms 后自动清除 | `data-state` 真实变化时；常态不闪烁 |
| 灵感标签 | 悬停上浮 1px、描边转冰蓝、文字转品牌色 | 悬停 |

所有列表动画只使用 `transform / opacity`，不改变布局高度；错峰入场只在首次渲染执行，避免每次刷新整列重播。

### 5.4 对话与工具

- 用户消息从右下方滑入 360ms；AI 消息从左下方滑入 420ms。
- 流式光标为冰蓝竖条，完成后由 `markDone` 一次性收尾，避免残留。
- 工具节点：等待（虚线）→ 执行中（蓝色脉冲）→ 成功（`nodePop` 缩放 0.6→1.25→1）→ 失败（红色实心）。
- 天气图标持续 6.5s 浮动；天气底纹按晴/云/雨/雪切换（光芒旋转、云团漂移、雨丝下落、雪点飘落）。
- 所有动画只由真实状态触发（工具事件、天气结果、请求结束）。

### 5.5 性能与无障碍

- `requestAnimationFrame` 单循环；`document.hidden` 时跳过绘制；页面隐藏即暂停。
- 只动 `transform / opacity / 颜色`；面板不随滚动做滤镜动画。
- `prefers-reduced-motion: reduce`：关闭全部动画与两个画布，保留静态层级（实测标题、卡片、输入区全部可见可用）。
- 小屏（<760px）粒子减半，视差幅度不变但绘制量降低。

## 8. 实测记录

- 七档视口逐张截图，0 横向溢出。
- 真实对话：3 次工具调用 → 时间线四态 → 天气卡显示真实数据（21°/13°、当前 16°、体感 15°、湿度 64%、西北风 1-3 级）与「22:03 更新」→ 状态转「已验证」。
- 错误态：CDP 拦截失败请求 → 中文提示 + 重试按钮 + Toast + Agent 置「异常」。
- 移动端抽屉：浅色面板、焦点进入首项、Esc 关闭回到触发按钮。
- `prefers-reduced-motion`：标题 opacity 1、状态面板 opacity 1、天气空状态可见、画布隐藏。
- 动效可观察性：菜单悬停高亮与指示条、刷新按钮旋转态、面板错峰入场、天气卡阶梯显现、状态点确认动效均已截图验证。
- 控制台无前端异常（仅被拦截请求的网络错误日志）。

## 9. 未覆盖事项

- 仅 Chromium 实机验证；Firefox/Safari 未实机测试（所用属性均为标准 CSS，`backdrop-filter` 带 `-webkit-` 前缀）。
- 移动端虚拟键盘行为依赖浏览器对 `100dvh` 与 `env(safe-area-inset-*)` 的实现，未真机验证。
- 工具时间线仍只存在于本次会话（后端未持久化工具事件），刷新后历史消息只有正文。
- 天气卡刷新后回到空状态，需要重新查询——不伪造数据的必然结果。
- 历史会话未按日期分组，仍按更新时间倒序平铺。
